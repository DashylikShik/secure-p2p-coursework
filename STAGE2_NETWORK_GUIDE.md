# Этап 2, часть 3 — сетевой пилот FIND_NODE

Этот набор файлов **дополняет** существующий проект. Старые `node.py`, `transport.py`, `identity.py`, `routing.py`, конфигурации и тесты остаются прежними. Из старых файлов изменяется только `protocol.py`: добавлены числовые типы кадров `FIND_NODE_REQUEST=3` и `FIND_NODE_RESPONSE=4`. Не заменяйте README, если вы уже редактировали его самостоятельно.

## Что умеет пилот

* 5 независимых логических узлов A–E (отдельные TCP-порты, ключи, routing table).
* Подписанные Ed25519 RPC `PING` и `FIND_NODE`, проверка `NodeID` по открытому ключу.
* Начальный bootstrap по **одному адресу IP:порт** (у рабочих узлов нет центрального каталога).
* Итеративный поиск с `ALPHA=3`: до трёх параллельных запросов за раунд.
* Отказ seed-узла B после discovery и последующий поиск E через оставшиеся контакты.
* JSON с трассами: число RPC, итераций, ошибки, время поиска.

**Ограничения.** Это учебный пилот, запущенный только на 127.0.0.1 и пока **без TLS**. Подписи помогают обнаружить изменение тела RPC и проверить связку ключ–NodeID, но не обеспечивают конфиденциальность и не заменяют доверенную взаимную TLS-аутентификацию. Повтор защищённого сообщения ещё не блокируется. Владелец адреса bootstrap пока не известен заранее — первая встреча не закреплена доверенным ключом. `STORE`, `FIND_VALUE`, refresh и republish ещё впереди.

## Установка в PyCharm

1. Закройте запущенные узлы.
2. Распакуйте архив в отдельную папку.
3. **Замените** только файл `protocol.py` на новую версию, добавляющую два типа RPC (старые сообщения остались прежними).
4. **Добавьте** новый `dht_network.py` рядом с `node.py`, `STAGE2_NETWORK_GUIDE.md` в корень, `scripts/dht_demo.py` и `tests/test_dht_network.py` в соответствующие папки.
5. Откройте CMD в корне проекта и выполните команды ниже.

```bat
cd /d "C:\Users\Пользователь\Desktop\p2p_stage1\p2p_stage1"
py -m unittest discover -s tests -v
py -m scripts.dht_demo
```

Если установлен `cryptography` из предыдущей части, дополнительная установка не нужна.

## Что показывать преподавателю

Трассу FIND_NODE: инициатор A на старте знает только B; D отсутствует в его таблице. A сначала опрашивает B, затем найденные через ответы контакты и действительно достигает D. После выключения B повторный поиск E остаётся успешным. Снимки таблиц и трассы сохраняются в `results/dht_pilot_*.json` (папка ignored в Git). Это пилот на 5 узлах, а не окончательный эксперимент на N=12.

## Безопасность и GitHub

Не загружайте `identity.pem` и другие закрытые ключи, а также **личный DOCX-конспект**. Если Git push из CMD пока недоступен, файл(ы) из этого обновления можно вручную добавить через GitHub Web UI; при загрузке `protocol.py` нужно именно заменить существующий файл. Репозиторий GitHub и локальный Git теперь могут иметь разные истории после браузерной загрузки: не делайте `push --force`, `reset --hard` и автоматические слияния без проверки.
