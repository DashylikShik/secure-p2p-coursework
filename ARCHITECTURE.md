# Проектное решение, этап 1

Тема: «Защищённая оверлейная сеть передачи данных на основе пиринговых протоколов».

- Уровень: упрощённый (предварительный выбор; согласовать с преподавателем).
- Язык: Python 3.11+ (проверить локальную версию).
- Масштаб итоговой сети: N = 12 отдельных процессов; на этапе 1 запускаются два узла.
- Запланированные параметры: K_BUCKET_SIZE = 3; ALPHA = 3; R = 3.
- Транспорт: TCP, стандартная библиотека Python `socket`.
- Сериализация: JSON (`json` из стандартной библиотеки).
- Межузловая защита в следующих этапах: TLS 1.3 с взаимной аутентификацией; защита end-to-end поверх туннеля.
- Запуск этапа 1: два независимых Python-процесса, каждый слушает отдельный TCP-порт.
- `protocol.py`: формирование и разбор кадров.
- `transport.py`: сетевые соединения, запрос PING, ответ PONG.
- `node.py`: запуск, чтение настроек и консольный интерфейс.
- `configs/`: параметры каждого узла; `tests/`: автоматические проверки.

Важно: этап 1 не реализует DHT, криптографию или туннель. Это запланировано следующими этапами. Начальное подключение на `127.0.0.1` не является распределённой сетью из 12 узлов.

## Выбор сериализации

| Критерий | JSON | MessagePack |
|---|---|---|
| Читаемость | Текст, можно открыть редактором | Бинарный формат, без декодера не читается |
| Подключение в Python | Встроенный модуль `json` | Обычно требуется внешняя библиотека |
| Размер | Может быть больше из-за текстовых ключей | Обычно компактнее для типизированных данных, зависит от содержимого |
| Развитие формата | Легко добавлять поля, нужна валидация | Легко добавлять поля, нужна валидация |

На этапе 1 выбран JSON, чтобы было проще проверять поля и отлаживать кадрирование. При расширении можно выполнить измерение размера на фиксированном наборе сообщений и дополнить сравнение. Во всех случаях размер `payload_length` отражает **байтовый** размер сериализованного payload, а не число символов.
